# Durable State

Serverless runtimes are stateless and short-lived. A worker invocation creates state, serves the request, and dies — anything kept in module scope is gone with it. Realtime connectivity normally adds the same burden in reverse: owning WebSockets, their lifecycle, and their cleanup.

`durable` removes both. The state lives in one persistent object — a Cloudflare Durable Object or any long-lived runtime — and short-lived workers sync against it through a bridge.

## The Durable Object

Your users can be served by different worker instances at the same time, and state kept in one worker is invisible to the others. The object is the one state every instance shares — so users see each other no matter which worker served them:

```ts
// src/visitors.ts — exported as a Cloudflare Durable Object
import { Durable } from '@irpclib/irpc';
import type { StateChange } from '@airlib/core';

export class Visitors {
  state = new Durable<Record<string, Visitor>>({});

  async replay(event: StateChange, emitter: string) {
    this.state.replay(event, emitter);
  }

  async subscribe(id: string) {
    return this.state.subscribe(id);
  }
}
```

:::tip[What we learn]
- `this.state.data` is the live state — the same reactive object you'd use anywhere, except it outlives the request.
- A change to it reaches every connected client, except the one who made it.
- The object's whole job is holding state and syncing it — no WebSocket code ever lives here.
:::

## Configure Wrangler

Tell the platform this class is a persistent object, so it keeps instances alive:

```toml
# wrangler.toml
name = "my-air-app"
main = "dist/server/worker.js"
compatibility_date = "2024-06-10"
compatibility_flags = ["nodejs_compat"]

[[durable_objects.bindings]]
name = "VISITORS"
class_name = "Visitors"

[[migrations]]
tag = "v1"
new_classes = ["Visitors"]
```

## The Adapter

The adapter is the one place that knows the platform — register it once, and everything else in your code talks to `durable`:

```ts
// src/worker.ts
import { createApp } from '@airlib/react/ssr';
import { durable } from '@irpclib/irpc';
import App from './app.js';
import router from './router.js';

let env: Env;

const worker = createApp(router, App);

durable.use({
  get(namespace, bindingKey) {
    const ns = env[bindingKey ?? 'VISITORS'] as DurableObjectNamespace;
    return {
      async replay(event, emitter) {
        const stub = ns.get(namespace);
        await stub.replay(event, emitter);
      },
      async subscribe(id) {
        const stub = ns.get(namespace);
        return stub.subscribe(id);
      },
    };
  },
});

export default {
  async fetch(request, incoming) {
    env = incoming;
    return worker.fetch(request, incoming);
  },
};
```

:::tip[What we learn]
- This is the only code that mentions the platform binding — switch platform, change only this file.
- `durable.get()` routes through this adapter. The namespace you pass selects the object, so every connection — every user, every request — syncs against the same state.
:::

## The Constructor

```ts
// src/pages/function.ts
import type { RemoteState } from '@irpclib/irpc';

export type Join = (visitor: Visitor) => RemoteState<Record<string, Visitor>>;

export const visitor = {
  join: irpc.declare<Join>('visitor.join', {
    seed: () => ({}),
    keepAlive: true,
  }),
};
```

```ts
// src/pages/constructor.ts
import { durable, stream } from '@irpclib/irpc';
import { visitor } from './function.ts';

irpc.construct(visitor.join, (user) =>
  stream(async (state) => {
    const { data } = await durable.get<Record<string, Visitor>>(user.id, 'visitors');

    data[user.id] = user;
    state.data = data;

    return () => {
      delete data[user.id];
    };
  })
);
```

:::tip[What we learn]
- `durable.get(user.id)` keys the connection by the user — a returning request reuses the existing connection instead of opening a new one.
- The returned `data` is live: mutate it, and the object and every other connected client update.
- The cleanup runs when the stream ends — page closed or connection dropped — so the user leaves the state automatically.
- `keepAlive` keeps the stream open without a timeout, so an idle connection isn't dropped.
:::

The client subscribes like any remote function — the returned state updates as users join and leave:

```tsx
import { Show } from '@airlib/react';
import { visitor } from './function.ts';

const presence = visitor.join.once({ id: 'alice', cursor: { x: 0, y: 0 } });

<Show when={() => presence.data}>
  {(data) => <div>{Object.keys(data).length} online</div>}
</Show>
```

## When to Use It

- **State across invocations** — counters, queues, game state, anything that must survive the current request on a stateless runtime.
- **Presence and shared cursors** — every visitor's cursor on one persistent object, immune to worker recycling.
- **Rooms and lobbies** — chat, multiplayer; the object holds the roster while workers come and go.

For one-way streaming — the server produces data the client consumes — see [Reactive Streaming](/docs/remote-function#reactive-streaming). For call-based remote functions, see [Remote Function](/docs/remote-function).
